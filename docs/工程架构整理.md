# 工程架构整理与改动指南

> 适用工程：`Pressure_Regulating_Box`（GD32L233RC，Keil MDK）
> 最后更新：2026-08-28（对应激光甲烷/定时开关阀/三组独立 I2C 重构后的代码状态）

---

## 1. 总体架构

### 1.1 分层与依赖方向

```
App（业务层：不碰寄存器/外设）
  │  只调用 Middle 接口 与 BSP 语义接口
  ▼
Middle（中间层：业务编排、协议、配置、上报）
  │  调用 Drivers / BSP
  ▼
Drivers（外设驱动：通信/传感器/存储传输）
  │  调用 BSP（延时、串口、电源）
  ▼
BSP（板级驱动：GPIO/电源/电机/LCD/深睡，自包含、零业务依赖）
```

**强制约定**：
- App 层不得出现 `gpio_*`、`rcu_*`、`pwm_*` 直接调用（main.c 启动段除外）。
- BSP 层不得 include Middle/App 头文件、不得引用业务全局变量。
- 平台 JSON 组包只能出现在 `Middle/report.c`。
- 各层向下依赖，禁止反向。

## 2. 核心设计约定

### 2.1 主状态机（main.c）

```
STATE_INIT → STATE_SLEEP → STATE_WAKEUP ─┬→ STATE_COLLECT → STATE_UPLOAD
                  ↑                       ├→ STATE_DOWNLINK
                  │                       ├→ STATE_ALARM
                  │                       ├→ STATE_BLE_OTA
                  │                       └→ STATE_CH4
                  └─────────────────────────────────────────┘
```

- 深睡：`wakeup.c` 统一入口，唤醒源 = RTC 闹钟 / LPUART / 按键 EXTI / 4G RI。
- 入睡前由 main.c 组装 `PmSleepCfg_t{lpuart_enabled, lcd_active, bt_on}` 传给 BSP，BSP 不读全局。
- `STATE_CH4`：激光甲烷采集,由 `g_ch4_request`(`gas_get` 触发)或 `laser_time` 位图命中整点时,在主循环 `STATE_SLEEP` 分支转入;不抢占网格采集/整点上报。

### 2.2 下行指令流程（downlink.c）

```
EC801E_ReadDownlink → parse_cmd(raw, &req)
   ├─ OTA（含 downloadUrl）→ ota_app_handle_upgrade_cmd
   ├─ 格式B（commandStr）→ CmdMap 映射为 id
   └─ 格式A（id/value）
        ↓
s_cmd_handlers 表（44 项，含 gas_get/laser_get/laser_set/msh_get/msh_set/closeoropen_*/table_*）→ h_xxx(id_val, cmd_val, raw_buf)
        ↓
report_publish_*（反馈/响应）
```

`s_cmd_map`（commandStr → id 映射）当前 47 项；`s_cmd_handlers`（id → handler 分发）当前 44 项。

### 2.3 上报（report.c）

- 平台 JSON 组包唯一出口，`EC801E_PublishRawJson` 只被 report.c 直接调用（驱动内部除外）。
- 模块内共享 1KB 缓冲 + 32B 时间戳，函数串行使用、禁止嵌套。

### 2.4 配置（eeprom_config.h 门面 + 三实现文件）

- **数据**：地址/magic/结构体/全局 extern/接口声明 → `eeprom_config.h`
- **持久化**：`config_store.c`（全局 g_\* 定义 + 读写 + load/save，含 `config_save_valve_timing/ch4_threshold/laser`）
- **策略**：`config_policy.c`（纯逻辑，无 EEPROM/串口）
- **CLI**：`eeprom_config.c`（串口解析 + 上电等待）

EEPROM 区块新增：定时开关阀(0xC8/0x490)、CH4 阈值(0xC9/0x4B0)、激光定时采集(0xCA/0x4C0)。芯片由 `app_config.h` 编译宏二选一(当前 `EEPROM_DRV_AT24C64` 8KB)，均走 IIC0(PB6/7)独立总线。

### 2.5 编码规则（重要）

- 工作区 `.c/.h` 为 **GBK**；入库时经 `.gitattributes`（`working-tree-encoding=GBK`）自动转 UTF-8。
- `docs/*.md` 为 UTF-8。
- 修改 `.c/.h` 时：若文件含中文注释，编辑后必须保持 GBK（可用 GBK→UTF-8 编辑→转回，或字节级 ASCII 替换）；`git diff` 若显示中文乱码说明编码被破坏。
- 新文件同样要转 GBK（纯 ASCII 内容则两种编码等价）。

### 2.6 低功耗

- 深睡路径统一走 `enter_deepsleep_mode()`：清唤醒标志 → 关软狗 → `gpio_enter_low_power`（未用引脚全 Analog）→ PMU 深睡 → 等唤醒源。
- 4G 省电：QSCLK/DTR（power.c）；弱信号自动断电（main.c 策略）。

## 3. 日常改动指南

### 3.1 新增一条 MQTT 下行指令

1. （格式B）在 `downlink.c` 的 `s_cmd_map` 增加 `commandStr → id` 映射；若平台用格式A（id/value），跳过此步。
2. 在 `downlink.c` 写 handler：
   ```c
   static void h_my_cmd(const char *id_val, const char *cmd_val, const char *raw_buf)
   {
       /* 业务逻辑；参数/响应用 report_publish_* */
   }
   ```
3. 在 `s_cmd_handlers[]` 登记：`{ "my_id", h_my_cmd },`（格式A 的 id 直接命中；格式B 经 CmdMap 归一后命中）。
4. 反馈用 `report_publish_feedback(码)`，单字段响应用 `report_publish_field/response`。
5. 编译 + 用平台下发验证。

### 3.2 新增/修改上报字段

- 只改 `Middle/report.c`（字段名、格式、缓冲）。
- 若需要新上报函数，加到 `report.h` 并保持"串行使用共享缓冲"约定。

### 3.3 新增配置项

1. 结构体字段：`eeprom_config.h`（配置结构体）。
2. 存储布局：`eeprom_config.h` 增加地址宏 + magic（注意区域不重叠）。
3. 读写：`config_store.c` 的 `config_load_all` / `config_save_*`。
4. 默认值：`app_config.h` 或 `eeprom_config.h` 的 `DEF_*`。
5. CLI 解析：`eeprom_config.c` 的 `parse_*` / `config_parse_and_apply`。
6. 平台指令：按 3.1 流程加 handler。

### 3.4 新增 BSP 模块 / 改引脚

- 引脚宏定义在**模块自己的头文件**（如 motor.h、power.h），不要放 app_config.h。
- BSP 模块不得 include Middle/App 头；需要的状态由调用方传参。
- 新增 `.c/.h` 后必须在 Keil 工程 `GD32L233R_EVAL.uvprojx` 对应组登记。

### 3.5 修改电机/LCD/4G 行为

- 电机：只改 `BSP/motor.c`（语义接口内部）；`App/valve.c` 不感知 PWM/GPIO 差异。
- LCD：显示逻辑在 `App/lcd_ui.c`，底层/关屏在 `BSP/slcd_seg.c`。
- 4G 电源/休眠：`BSP/power.c` + `main.c` 策略；AT/协议在 Drivers（待主题 B 拆分）。
